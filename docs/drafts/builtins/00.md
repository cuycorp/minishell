You're absolutely right — **some builtins need to be executed in the parent process**, while others **can and should be executed in a child process**. Let's break it all down clearly, including **why**, and then adjust your execution model accordingly.

---

### 🔁 RECAP: Why Builtins Behave Differently

Builtins are shell commands implemented **internally** and **don’t require creating a new process**.

However:

* **Builtins that affect the shell’s state (like `cd`, `exit`, `unset`, `export`)** must run in the parent, otherwise the effect is lost after the child exits.
* **Builtins like `echo`, `pwd`, and `env`** don’t modify the shell’s state — they can safely be run in a child.

---

### ✅ Run Builtins in **Parent Process**

These **must** be executed in the parent process (inside the shell):

* `cd`
* `exit`
* `export` *(if modifying env vars)*
* `unset`

> If you run these in a child, changes won’t persist in the shell (e.g., `cd` won’t change directory in the parent, and `exit` will just exit the child, not the shell).

---

### ✅ Run Builtins in **Child Process**

These can be safely run in a child:

* `echo`
* `pwd`
* `env`
